## File map (all Markdown tables; rows with "(example)" are ignored)
- docs/project.md: Key | Value (name, goal, audience, schedule calendar)
- docs/requirements.md: ID | Requirement | Source | Priority
- docs/decisions.md: append-only log; change via new row + Supersedes
- docs/assumptions.md: everything Claude inferred; Status Open/Confirmed/Rejected
- docs/open-questions.md: ID | Question | Blocks (IDs) | Status
- wbs/wbs-outline.md: indented list, `- 1.2.3 Name`
- wbs/wbs-dictionary.md: one row per work package

## WBS rules
- 100% rule: children sum to exactly the parent's scope; nothing outside scope.
- Elements are deliverables named as nouns, not activities.
- Work packages: 8–80 hours, exactly one owner, at least one Req ID.
- Numbering 1 / 1.1 / 1.1.1; max 4 levels.

## Sources and unknowns
- Decisions: Source = user or stakeholder:name; accepted defaults = user. Inferences go to assumptions.md.
- [OPEN] marks unknown cells. Never invent facts.

## Terseness
- Working files: short phrases, not sentences. No filler, no hedging. Refer by ID.
- Max 15 words per free-text cell. No invented abbreviations.
- Copy the style of each template's example row.
- Readable prose only in exports, assembled by the build script.

## Working style
- Targeted file edits only. No recaps after edits.
- Batched questions with marked defaults.

## Phases and exit criteria
1. Init: workspace committed. Exit: all files exist.
2. Gather (/wbs:gather): Exit: no open questions affecting structure.
3. Outline (/wbs:draft outline): Exit: levels 1–3 cover every Req ID; user reviewed.
4. Dictionary (/wbs:draft dictionary): Exit: every work package row complete or [OPEN].
5. Check (/wbs:check): Exit: no blocking issues; open assumptions reviewed.
6. Export (/wbs:draft export): Exit: exports/WBS.xlsx and exports/WBS.md built.
